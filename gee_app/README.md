# BareSand: мини-приложение Google Earth Engine

Интерактивная карта к статье о маске оголённых песков севера Западной Сибири по Sentinel-2 и генезисе песков.
Приложение работает в Code Editor и публикуется как Earth Engine App. Версия 18.11.2026: генезис v7 (06.10.2026),
кадастровые группы техногенных песков в итоговой редакции v7b (03.11.2026, `exports/final/*_v7b.gpkg`). Состояние:
ассеты загружены скриптом `python/150_gee_upload.py` (кадастровые слои v7b 03.11.2026), скрипт проверен на настоящих
ассетах через Python API и в Code Editor (раздел 8). Опубликован 19.11.2026: https://nodal-thunder-481307-u1.projects.earthengine.app/view/baresand (Cloud-проект
nodal-thunder-481307-u1, исходник: скрипт Code Editor sand_ZapSib/baresand_app, доступ по ссылке, в галерею не добавлен;
ассеты всем на чтение не открывались). Исходный код опубликованного App виден любому посетителю.

| Файл | Что это |
|---|---|
| `baresand_app.js` | приложение (Code Editor, ui API, JavaScript ES5); настраивается только раздел 1 |
| `prepare_assets.py` | альтернативный путь: подготовка файлов к ручной загрузке (отбор и нормализация полей, упрощение с откатом, проверки, ZIP и COG); для текущих ассетов не использовался |
| `README.md` | этот файл: что показывает приложение, ассеты, публикация |
| `_test/` | проверки: подмножество у Надыма (`out/`, результаты проб, в выпуск не входят), прогон приложения с заглушками (`mock_run.js`), сверка реестра сцен (`scene_registry_check.*`, охваты следов `scene_footprint_cover.csv`), манифест пробы на 50 тыс. контуров (`manifest_50k.csv`) |

## 1. Что показывает приложение

Интерфейс (19.11.2026, по просьбе автора: минималистичный, шрифт крупнее): белая панель шириной 400 px, основной
шрифт 14 px. Сверху заголовок, одна строка о данных, точность эоловых песков и подсказка о щелчке. Ниже группы:
«Результат» (генезис, плотность, техногенные пески и отводы ЕГРН), «Снимки и маска» (сцены Sentinel-2, маска 10 м,
первичный вектор), «Справочные слои» (граница района, покрытие, тайлы, дороги, рельеф, вода, лесной покров),
«Скачать контуры» и «О проекте» (ссылки на методику, статью и репозиторий, когда они заданы в `LINKS`; источники).
У выключенного слоя видна только строка с флажком; у включённого раскрываются легенда и ползунок непрозрачности (в
процентах). Ширины подобраны так, чтобы строки не выходили за панель: иначе Code Editor рисует под строкой полосу
прокрутки (так было в версии 18.11.2026). Щелчок по карте открывает карточку атрибутов всех включённых слоёв, у
которых есть атрибуты. Подложки: светлая (по умолчанию), спутник, рельеф. Стартовый масштаб 5.

Скачивание контуров: слой (генезис или одна из трёх кадастровых групп), формат (GeoJSON, KML, CSV) и кнопка
«Получить ссылку на видимую область». Приложение считает контуры в видимой области и, если их не больше 50 000,
строит ссылку `getDownloadURL` на стороне Earth Engine. На масштабе мельче 8 подсчёт не запускается (по всей области
он идёт около 30 с), выводится подсказка приблизить карту. Проверено 19.11.2026: 20 766 контуров генезиса дают GeoJSON
18 МБ за 11 с. Shapefile в списке нет: Earth Engine в этот день отвечал на выгрузку SHP ошибкой 500 даже для таблицы
из одного объекта (NoSuchFileException на стороне сервера). Геометрия ассетов упрощена на 10 м; ссылка на полные слои
(`LINKS.data`) появится после выкладки данных. Подробное описание метода для читателя: [../docs/INTERPRETATION.md](../docs/INTERPRETATION.md).

### Группа 1. Исходные снимки

Сцены `COPERNICUS/S2_SR_HARMONIZED` из реестра `exports/aux/tile_scenes.csv` (скрипт `python/126_tile_scenes.py`).
Формат реестра: 128 строк, поля `tile` (тайл MGRS), `cloud_asset` (облачность из канала `cloud_score` ассета маски),
`scene_id` (system:index сцены), `date`, `cloud_scene` (CLOUDY_PIXEL_PERCENTAGE), `rank`, `match` (облачность совпала
с ассетом). Список встроен в приложение (переменная `SCENES`), коллекция собирается фильтром
`ee.Filter.inList('system:index', ...)`. Режимы: обзорная мозаика (по умолчанию), мозаика сцен реестра или один тайл;
синтезы с каналами и пределами
из `gee_scripts/21_production_classify.js`: ложные цвета B8-B4-B3 (180-4950), натуральные B4-B3-B2 (0-3000),
SWIR B12-B11-B4 (0-4000).

Важно: реестр восстановлен повторением правила выбора, и для большинства тайлов он не совпадает со сценой, по которой
экспортирован ассет маски (раздел 7). Поэтому у каждого тайла в приложении показан статус сверки, а в списке сцен
тайла, кроме сцены реестра, есть кандидаты, совпавшие со следом ассета. Статус `ok` означает совместимость по охвату и
облачности, а не установленную исходную сцену: у 19 из 23 таких тайлов совпавших кандидатов несколько (ревью Astra,
13.10.2026); в приложении статусы сформулированы как «совместима со следом маски».

Обзорная мозаика: по одной сцене на тайл, подобранной по следу ассета маски (раздел 7, уточнение 19.11.2026); она
закрывает 98,4 % покрытия маски, мозаика сцен реестра закрывала 45 %, потому что у многих тайлов сцена реестра узкая
полоса на краю витка. Карточка сцены по щелчку описывает показанную сцену.

### Группа 2. Первичный вектор маски

Первичный вектор, то есть маска до атрибуции генезиса, это `exports/baresand_contours_v2.gpkg`, слой `contours`:
результат векторизации `python/30_vectorize_local.py` (VERSION v2) растровой мозаики `baresand_mask_AOI_v2`
(`gee_scripts/22_mosaic_export.js`). 574 520 полигонов, EPSG:3576, поля id, area_ha, area_km2, perimeter_m,
compactness, centroid_lon, centroid_lat (два последних в метрах EPSG:3576, а не в градусах); связные области не меньше
900 м² (MMU). Это база id итогового слоя (`docs/genesis_methodology_review.md`: «v2 принята как база (8 155.7 км²,
574 520 контуров)»). Файл `exports/baresand_genesis_v2.gpkg` первичным вектором не является: это ранняя попытка
атрибуции (584 580 полигонов, EPSG:4326, поля genesis и reason), а не векторизация маски.

Слои группы: растр маски 10 м (с масштаба 10) и границы первичных контуров (с масштаба 11). Ассет `contours` (150)
содержит только поле id, поэтому в карточке контура площадь пуста.

## 2. Лимиты GEE и как приложение их обходит

- Таблица на 575 тыс. полигонов допустима (предел GEE 100 млн объектов в таблице, 1 млн вершин на объект; в пробе
  максимум 3 183 вершины у контура генезиса и 15 655 у части anthro_in). Медленно не хранение, а отрисовка: рисовать
  575 тыс. полигонов на мелких масштабах при каждом запросе плитки дорого.
- Мелкие масштабы: заливка генезиса берётся из растра классов `genesis_r50` (150 `--class-raster`: `reduceToImage` по
  полю gcode упрощённой таблицы, 50 м, EPSG:3576, пирамиды MODE). Пирамиды MODE не гарантируют сохранение малых классов
  на обзорных масштабах. Без этого растра заливка из таблицы рисуется только с масштаба 9, и на стартовом масштабе 5
  основной результат не виден (ревью Astra, A2).
- Растр маски `baresand_mask_AOI_v2` экспортирован с пирамидами MEAN и значениями 0/1, поэтому на мелких масштабах
  песок в нём исчезает (проверено: в точке Надымских песков значение 1 при шаге 10-160 м и 0 при 640 м). Приложение
  показывает только каноническую мозаику `baresand_mask_AOI_v2` (канал sand_mask) с масштаба 10, а мельче
  подставляет охват контуров по растру классов `genesis_r50`.
- Границы контуров рисуются из таблиц (`ee.Image.paint`) с масштаба 11, кадастровые группы с масштаба 8. Если этого
  мало, можно экспортировать FeatureView (раздел 4) и вписать их в `FEATURE_VIEWS`: тогда векторы рисует FeatureView с
  прореживанием по площади.
- Обзор на всю территорию дают растры плотности (10 км).
- Щелчок: запрос `filterBounds` к таблице в радиусе трёх пикселей экрана (не меньше 5 м), выбирается ближайший объект
  (внутри полигона расстояние 0). Каждый слой запрашивается отдельно, ошибка одного не мешает другим. Радиус на мелких
  масштабах велик (около 5,9 км на масштабе 5), запросы не ограничены масштабом видимости (раздел 9).
- Производительность с настоящими ассетами не измерялась. Community Tier Earth Engine даёт ограниченный объём
  вычислений в месяц, при превышении квоты GEE отвечает ошибкой 429.

```javascript
var FOLDER = 'projects/nodal-thunder-481307-u1/assets/ZapSib_baresands/app';

Export.image.toAsset({

  description: 'genesis_r10', assetId: FOLDER + '/genesis_r10',
  region: aoi.geometry().bounds(), crs: 'EPSG:3576', crsTransform: [10, 0, -1299430, 0, -10, -1776220],

});
['genesis', 'contours', 'anthro_in', 'anthro_exceed', 'anthro_noallot'].forEach(function(name) {
  Export.table.toFeatureView({

    description: name + '_fv', maxFeaturesPerTile: 1500, thinningStrategy: 'HIGHER_DENSITY',
    thinningRanking: ['area_ha DESC'], zOrderRanking: ['area_ha DESC']
  });
});
```

Растр 10 м по району содержит около 10,7 млрд ячеек; длительность экспорта не оценивалась, `maxPixels` не снимает
ограничений времени и памяти. Astra рекомендует строить растр классов локально (GDAL или rasterio по точному v7 до

## 7. Реестр сцен Sentinel-2: что выяснилось при подготовке

Все 128 сцен реестра есть в коллекции (проверено `ee.Filter.inList`). Но по следу ассета маски они в большинстве не
подтверждаются (`_test/scene_registry_check.py`, результат `_test/scene_registry_check.csv`):

- ассет тайла экспортирован с `region: scene.geometry()` в EPSG:4326 (`21_production_classify.js`), поэтому его след
  это прямоугольный охват следа сцены, по которой он сделан;
- охват следа ассета ограничен у 126 тайлов (у 41WPQ и 41WPR след не ограничен, сверка невозможна);
- охват сцены реестра совпал с охватом ассета (IoU охватов ≥ 0,98) у 26 тайлов, из них облачность совпала с
  `cloud_score` ассета у 23; у 100 тайлов сцена реестра другая: у 73 из них охват сцены меньше половины охвата
  ассета, у 40 меньше десятой (узкая полоса на краю витка с нулевой облачностью, которую правило «минимальная
  облачность» ставит первой), а ассет покрывает весь тайл (`_test/scene_footprint_cover.csv`);
- среди кандидатов (то же правило отбора: июль-сентябрь 2020-2025, облачность < 15 %) охват и облачность ассета
  совпали ровно у одной сцены в 26 тайлах, у 2-12 сцен в 72 тайлах, ни у одной в 28;
- проверка `python/127_tile_scene_footprint_check.py` дала «0 из 128», потому что сравнивала след сцены со следом
  ассета (а это охват в градусах) и не учитывала неограниченные следы; ответа о реестре она не даёт.

Следствия: приложение S7 («совпадение с облачностью 120 из 128 слабо подтверждает выбор») нужно уточнить, а
распределение сцен по годам и месяцам относится к реестру, а не к фактически обработанным сценам; сцены реестра для
100 тайлов, по-видимому, не те, по которым строилась маска. Причины не выяснялись: возможно, коллекция пополнилась после
экспорта масок (апрель-май 2026), или при обработке использовалась другая версия правила. Проверить можно по сохранённым
скриптам `21_<тайл>` в аккаунте GEE (напечатанный при запуске `system:index`) или по истории задач. В приложении у
каждого тайла показан статус (`ok`, `fp`, `alt`, `no`, `na`) и список кандидатов.

Уточнение 19.11.2026 (`_test/scene_match_precise.py` -> `_test/scene_match_precise.csv`, перенос в приложение
`_test/scenes_to_app.py`). Канал `cloud_score` у всех 126 ассетов с ограниченным следом равен ровно 0: исходные сцены
были с облачностью 0 %. В текущем каталоге у сцен с тем же охватом следа облачность обычно 0,0001-0,001 %, а ровно 0
бывает у узких полос края витка; похоже, метаданные каталога пересчитаны после экспорта масок. Прежняя сверка сравнивала
облачность с допуском 0,001 % и поэтому находила по несколько «совпадающих» сцен; совпадения при точном сравнении:
одна сцена у 6 тайлов, 2-3 у 4 тайлов. Для остальных 116 тайлов приложение показывает наименее облачную сцену с тем же
охватом, что у следа маски (то же правило отбора, ограниченное охватом); у 41WPQ и 41WPR (след не ограничен) сцену
реестра. Такая обзорная мозаика закрывает 98,4 % покрытия маски (мозаика реестра 45 %). Автор подтверждает: в его
мозаике пробелов не было, то есть сцены покрывали тайлы целиком. Режим «сцены реестра» из приложения убран.

Уточнение 19.11.2026 (сцены восстановлены по копиям скрипта тайлов в репозитории GEE автора
users/<автор>/sand_ZapSib, папка rf; итоговые маски «с _ суффиксом» сделаны копиями 21_<тайл>_.js,

## 9. Открытые вопросы и известные несоответствия

1. Реестр сцен (раздел 7): уточнить по аккаунту GEE и решить, что показывать в группе 1 и писать в приложении S7;
   статусы сцен сформулировать как «совместима по охвату и облачности, исходность не установлена».
2. Схема ассетов 150 беднее расширенной схемы `prepare_assets.py`: у генезиса нет `rule`, `rule_step`, `gen_main`,
   типа отмели, метки автора, кадастровых полей; у первичного вектора нет `area_ha`. Приложение показывает то, что
   есть: у генезиса класс, площадь и происхождение класса (`step6_rule`, пусто = каскад правил шагов 1-5), у первичного
   вектора id; кадастровые коды `grp`, `kind`, `under` переводятся словами в приложении (18.11.2026). Дороги
   рисуются (поля `cls` и `winter` в ассете `roads` есть).
3. Исправлено 18.11.2026 (ревью Astra, A5, A7): карточка сцены описывает показанную сцену; запрос генезиса учитывает
   отключённые классы; ответ «ассет не найден» перепроверяется при следующем включении слоя.
4. Растр классов `genesis_r50` строится из упрощённой таблицы с шагом 50 м: малые контуры на обзорных масштабах могут
   пропадать (пирамиды MODE не гарантируют сохранения малых классов); это стоит подписать в панели.
5. Месторождения (`oilfields/Efield_region.shp`): источник и условия распространения не установлены; в публичное
   приложение не входят.
6. Поле `not_sand_suspect` (два смысла) в приложение не выведено; если нужно, разделить поле в продукте.
7. В `LINKS` ссылки на репозиторий и методику вписаны 20.11.2026 и показаны в панели «О проекте»; ссылки на статью
   (`article`) и выкладку полных слоёв (`data`) пусты и не показываются: вписать DOI после выхода статьи и адрес
   выкладки, когда она появится, затем переопубликовать App.
8. `_test/out/` (ZIP, SHP, TIF проб) в выпуск не входит; `_test/mock_run.js` обновлён под схему 150 (18.11.2026).
