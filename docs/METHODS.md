# Описание алгоритмов

Документ подробно описывает обработку, кратко изложенную в статье «Оголённые пески севера Западной Сибири: уточнение
карты и оценка точности»: от выбора сцен Sentinel-2 до итоговых слоёв, правила и пороги атрибуции генезиса, оценку
точности и сопоставление техногенных песков с земельными отводами. Дополнительные таблицы и результаты приведены в
[supplement/](../supplement/README.md), порядок дешифрирования в [INTERPRETATION.md](INTERPRETATION.md), слои и поля в
[DATA.md](DATA.md).

**Обозначения.** Параметры приводятся по коду: имя константы или значения по умолчанию (`MMU_M2 = 900`) либо ключ
командной строки (`--flood 0.2`). Скрипты указаны номерами или путями внутри [src/](../src/README.md)
(src/python/, src/gee_scripts/). Площади, расстояния и буферы считаются в равноплощадной азимутальной проекции Ламберта
EPSG:3576, если не указано иное. A: площадь контура, P: его периметр. Доли заданы в диапазоне 0-1, повторяемость воды
JRC GSW (occurrence) в процентах 0-100. Контур: связный полигон маски (раздел 4); остаток: контуры, не получившие класса
на предыдущих шагах каскада.

## 3. Классификация сцен

### 3.1. Классы покрова и обучающие точки

Классы `CONFIG.CLASSES` (gee_scripts/00_config.js): 0 bare_sand, 1 lichen_barren, 2 gravel, 3 bare_peat,
4 anthropogenic, 5 vegetation, 6 water, 7 snow_ice, 8 fire. В скрипте массовой обработки
(gee_scripts/21_production_classify.js) обязательны два слоя обучающих точек: sand (код 0, 15-20 точек) и lichen (код 1,
10-15 точек); слои fire (8), vegetation (5) и anthropogenic (4) добавляются, если такие поверхности есть на сцене. Точки
расставляются в Code Editor через Geometry Imports (тип MultiPoint), одна точка соответствует одному пикселю; выборка
своя для каждой сцены. Значения признаков в точках:
`stack.sampleRegions({collection, properties: ['class'], scale: 10})`.

Вода и густая растительность отсекаются порогами до случайного леса (п. 3.4), поэтому случайный лес разделяет песок и
спектрально сходные открытые поверхности, прежде всего лишайниковую пустошь. Маска песка: пиксели класса 0.

### 3.2. Облачная маска

```
cloudMask = NOT (SCL ∈ {3, 8, 9, 10})      // тени облаков, облака средней и высокой вероятности, перистые облака
masked    = scene.updateMask(cloudMask)
```

Класс SCL 5 (открытый грунт) не маскируется. Класс SCL 11 (снег) в массовой обработке не маскируется: севернее
67° с. ш. алгоритм SCL относит яркий песок к снегу.

### 3.3. Признаки

Стек из 18 признаков: 10 каналов (B2, B3, B4, B5, B6, B7, B8, B8A, B11, B12), 7 индексов и яркость.

```
NDVI       = (B8 - B4) / (B8 + B4)
BSI        = ((B11 + B4) - (B8 + B2)) / ((B11 + B4) + (B8 + B2))
DBSI       = (B11 - B3) / (B11 + B3) - NDVI
MBI        = (B11 - B12 - B8) / (B11 + B12 + B8) + 0.5
MNDWI      = (B3 - B11) / (B3 + B11)
NDRE       = (B8A - B5) / (B8A + B5)
NDMI       = (B8 - B11) / (B8 + B11)
Brightness = (B2 + B3 + B4 + B8) / 4
```

Каналы 20 м используются с разрешением, заданным при выборке точек и экспорте (10 м). Рельефные признаки в стек
классификации покрова не входят.

### 3.4. Двухэтапный классификатор

1. Пороговый предфильтр: `bareMask = (MNDWI ≤ MNDWI_WATER_MAX) ∧ (NDVI ≤ NDVI_VEG_MAX)`, `MNDWI_WATER_MAX = 0`,
   `NDVI_VEG_MAX = 0.40`. Порог NDVI 0,40 учитывает мокрый песок около 68° с. ш., у которого из-за субпиксельного мха
   NDVI достигает 0,36: на сцене Яратто полнота выделения песка при пороге 0,40 составила 0,90 против 0,55 при 0,25.
2. Случайный лес `ee.Classifier.smileRandomForest`: `RF_TREES = 200`, `RF_MIN_LEAF = 5` (minLeafPopulation),
   `RF_BAG_FRACTION = 0.5`, `RF_SEED = 42`; входы: все 18 признаков. Классифицируются только пиксели `bareMask`; песок:
   класс 0.

### 3.5. Постобработка и экспорт

```
sandMask = classified.eq(0).updateMask(bareMask).selfMask()
           .connectedPixelCount(16, true).gte(MMU_PIXELS)     // 8-связность, MMU_PIXELS = 9 (900 м²)
           .focal_mode({radius: 1, kernelType: 'square'})     // фильтр большинства 3 × 3
           .unmask(0)
```

Экспорт `Export.image.toAsset`: канал sand_mask (0/1), `scale = 10`.

### 3.6. Калибровка и выбор метода

Шесть калибровочных сцен (`CONFIG.CALIBRATION_SCENES`: Надымские пески, Яратто, терраса р. Надым, Ноябрьск, Тазовская
губа, Гыданская гряда), скрипт gee_scripts/17_validation.js: обучение на точках sand и lichen, контрольные точки
test_sand и test_not_sand, матрица ошибок `errorMatrix`, общая точность, каппа, точность производителя и пользователя

Методы (пороговый, K-средних, случайный лес по спектральным признакам, двухэтапный, случайный лес по эмбеддингам

### 3.7. Сшивка тайлов

gee_scripts/22_mosaic_export.js (вариант на Python: python/22_run_mosaic.py):

1. из маски каждого тайла берётся sand_mask, `selfMask()`, перепроецирование в EPSG:3576 с шагом 10 м (`TARGET_CRS`,

## 4. Векторизация и минимальная картографируемая единица

python/30_vectorize_local.py:

1. виртуальный растр из тайлов GeoTIFF маски района;
2. векторизация окнами `WINDOW_M = 50 000` м с перекрытием `OVERLAP_M = 2 000` м, `rasterio.features.shapes` по
   значению 1 (4-связность);
3. объединение полигонов (`unary_union`, склейка на швах окон) и разбиение на связные компоненты;
4. площадь и периметр в EPSG:3576; фильтр `MMU_M2 = 900` м² (9 пикселей);
5. поля: id (1..N), area_ha, area_km2, perimeter_m, compactness = 4πA/P² (0-1), координаты центроида в EPSG:3576.

Первичный вектор содержит 574 520 контуров. Минимальная единица проверяется дважды: в Earth Engine по 8-связной группе
пикселей (п. 3.5) и при векторизации по площади 4-связного полигона. Наименьшая площадь контура итогового слоя 900 м².
При последующих операциях с геометрией: сухие части разреза шага 2 менее 2 га остаются в отмели (`MIN_PART_HA = 2.0`);
при разделении смешанных контуров части менее 900 м² присоединяются к соседней части того же контура с самой длинной
общей границей; при сопоставлении с отводами учитываются части за полосой допуска не менее 900 м².

## 5. Каскад атрибуции генезиса (шаги 1-5)

### 5.0. Общая схема

- Атрибуция выполняется по контурам после спектральной классификации и не меняет решения «песок / не песок». Каждый
  контур получает один класс; смешанные контуры делятся на части (шаг 2, экспертные разрезы, v5).
- Классы в поле `genesis`: shoal (морская отмель), river_shoal, lake_shoal, anthropogenic, aeolian, undefined.
  Основной класс в поле `genesis_main`: alluvial_littoral, aeolian, anthropogenic, undefined; тип отмели в поле
  `shoal_type` (sea, river, lake) с источником `shoal_type_src` (rule, model, owner). Отмель любого типа образует один
  основной класс, тип отмели является второстепенным атрибутом.
- Порядок шагов: 1 морские отмели, 2 речные и озёрные отмели, 3 техногенные пески, 4 эоловые и неопределённые, 5
  уточнение по рельефу (неопределённые и эоловые у русел), 6 неопределённый остаток (раздел 6). Каждый шаг работает с
  остатком предыдущего.
- Отмели выделяются до техногенного шага. Контуры отмелей с техногенным следом не менее 30 % площади (участки и
  сооружения ЕГРН или объекты OSM; python/84_cascade_order_check.py, `--frac 0.30`) отмечены полями
  `anthro_late_suspect` и `anthro_footprint`: 1 771 контур, 65,2 км² (2,1 % площади отмелей на момент шага 4).
- Пороги шагов 1-4 подбирались на эталонах шагов, отобранных из результатов правил и дополненных трудными случаями
  ([S3](../supplement/S03_genesis_cascade.md)).

### 5.1. Шаг 1: морские отмели

Признаки (python/44b_sea_distance_osm.py):
- море: территория вне land polygons OSM в полосе `STRIP_M = 25 000` м вокруг границы района;
- отсечка рек по секторам долготы `RIVER_CUTOFFS` (долгота от, до, широта отсечки): (-180°, 74°, 67,0°),
  (74°, 80°, 67,3°), (80°, 180°, 69,7°); берег южнее отсечки считается речным (Обь, Таз и Пур, Енисей);
- западный берег Енисейского залива (69,7-71,7° с. ш.) задаётся по GSW occurrence ≥ 80 (`GSW_PERM_OCC = 80`) в окне
  `YENISEI_GSW_BOX` (80,0-84,8° в. д., 69,7-72,2° с. ш.);
- прибрежная зона: контуры ближе `COASTAL_ZONE_M = 5 000` м к границе района и севернее `COASTAL_LAT_MIN = 66°`;
- dist_sea_m: расстояние от контура до морской береговой линии; hnd_min: минимум MERIT HND по контуру
  (python/32a_step1_littoral.py); буфер берега `SHORE_BUFFER_M = 700` м по обе стороны линии.

HND используется как мягкий признак: у обрывистых берегов пиксель MERIT 90 м захватывает бровку, и пляж под обрывом

Разрез крупных контуров (`GIANT_MIN_HA = 20`, `SPLIT_MIN_FRAC = 0.05`): контур не менее 20 га, прошедший правило и
пересекающий буфер берега, делится по буферу. Часть в буфере остаётся морской отмелью под исходным id, часть вне буфера
становится новым контуром остатка с `parent_id`. Если вне буфера менее 5 % площади, контур не делится; если в буфере
менее 5 %, контур целиком передаётся в остаток. Контур 574532 (76,9 км², северо-запад Ямала) по экспертной проверке

### 7.3. Контрольная выборка итогового слоя (T3)

```
p = Σ_h A_h · p_h / Σ_h A_h,    p_h = Σ_{i∈s_h, метка = техногенный} a_i / Σ_{i∈s_h} a_i
```

с точной границей Клоппера-Пирсона по числу контуров (все верны: нижняя граница 0,025^(1/n); ни одного: верхняя

## 8. Оценка точности

### 8.1. Объект оценки

Оценивается правильность единой метки контура внутри маски с весом по его площади; полнота маски и точность отдельных
пикселей не оцениваются. Объект: версия карты на момент отбора выборки (до точечных правок); совокупность
зафиксирована python/118_validation_v4_pop.py. Во всех расчётах единицам выборки возвращается класс на момент отбора.
Проверяемая часть маски (домен U): 573 438 контуров, 8 061,0 км²; из отбора исключены 1 587 контуров (94,4 км²),
размеченных ранее при разработке правил (домен E).

### 8.2. Выборка

- Страты: основной класс карты (отмели, эоловые, техногенные, неопределённые) × размер (менее 1 га, 1-20 га, не менее
  20 га); объёмы заданы до разметки.
- Отбор (105 `--arms`): простая случайная выборка внутри страты без ранее размеченных контуров; страта крупных
  неопределённых (4 контура) обследована сплошь.
- Приёмы: V1, 176 контуров во всех стратах; V1b, 60 контуров не менее 20 га (распределение по Нейману по оценкам V1);
  V1c, 40 контуров не менее 100 га. Для V1c страты не менее 20 га разделены на 20-100 га и не менее 100 га: 488 контуров
  не менее 100 га (0,08 % числа контуров) занимают 14,7 % площади маски.
- Эталон: экспертная метка в окне проверки без класса карты (п. 6.1). Отмель любого типа считается отмелью; «не песок»
  и «смешанный» являются отдельными категориями эталона; смешанные контуры учитываются как ошибка.

### 8.3. Оценки по площади

Оценка отношения по стратам (python/119_validation_v4.py `--batches V1,V1b,V1c --split-ha 100`). Площадь ячейки
матрицы ошибок (класс карты k, эталонный класс j):

```
Â_kj = Σ_h A_h · ( Σ_{i∈s_h} a_i · I(m_i = k, r_i = j) / Σ_{i∈s_h} a_i )                (S6.1)
```

где A_h: площадь страты h в домене U, км²; s_h: единицы выборки страты h; a_i: площадь единицы i; m_i: класс карты
единицы (в основном расчёте совпадает с классом страты, и S6.1 сводится к формуле (2) статьи); r_i: эталонный класс;
I: индикатор. Строки матрицы: отмели, эоловые, техногенные, неопределённые; столбцы: отмели, эоловые, техногенные,
не песок, смешанные.

```
UA_k = Â_kk / Σ_j Â_kj                      точность пользователя (строка карты целиком, включая «не песок» и «смешанные»)
PA_k = Â_kk / Σ_m Â_mk                      точность производителя (столбец эталона, включая строку неопределённых)
F1_k = 2 · UA_k · PA_k / (UA_k + PA_k)
OA3  = Σ_{k∈3 класса} Â_kk / Σ_{k∈3 класса, j} Â_kj          (общая точность трёх основных классов)
OA4  = Σ_{k∈3 класса} Â_kk / Σ_{все k, j} Â_kj               (с учётом неопределённых)
площадь класса j по эталону = Σ_k Â_kj
```

Каппа рассчитывается по четырём категориям: три класса и «прочее» (карта: неопределённый; эталон: не песок и
смешанный). Интервалы: процентильный бутстрэп внутри страт (`B = 2000`) при окончательном разбиении на страты; страты,
обследованные сплошь, не пересэмплируются. Результаты: [S6](../supplement/S06_accuracy.md).

### 8.4. Техногенные пески

Техногенный класс выделен как экспертный класс по косвенным признакам (объекты OSM, участки и сооружения ЕГРН, история
поверхности по Global Forest Change и Landsat 1984-1995 гг., экспертные метки), поэтому показатели точности для него не

none = t за вычетом всех участков.

```
cad_in_ha  = Σ_{g ∈ {ind, np, terr, vri, ezp}} area(t ∩ участки g)
cad_out_ha = Σ_{g ∈ {big, unk, forest, agri, misc}} area(...) + area(none)
s(t)       = cad_in_ha / (cad_in_ha + cad_out_ha)           (поле in_pct = 100 · s(t))
E_d(t)     = части t \ buffer(P_in, d) площадью ≥ 900 м²     (определено, если dist(t, P_in) ≤ d)

allot(t)   ⇔ dist(t, P_in) ≤ 10 м
touch(t)   ⇔ allot(t) ∧ area(E_10(t)) > 0 ∧ s(t) < 0,10       (TOUCH_FRAC = 0.10)
noallot(t) ⇔ ¬allot(t) ∨ touch(t)                            статус «без отвода», площадь группы = area(t)
exceed(t)  ⇔ ¬noallot(t) ∧ area(E_10(t)) > 0                 статус «превышение отвода», площадь группы = area(E_10(t))
in(t)      ⇔ ¬noallot(t) ∧ area(E_10(t)) = 0                 статус «в отводе»
anthro_in  = t ∩ P_in для контуров со статусами «в отводе» и «превышение отвода»
```

Допуск d = 10 м равен размеру пикселя маски; вариант d = 20 м рассчитан для оценки чувствительности (поле
`cad_exc20_ha`). Полосы допуска вне отводов и части за полосой менее 900 м² ни в одну группу не входят, поэтому сумма
трёх групп меньше площади класса.

### 9.5. Возраст поверхности

Поле `age2000`: доля открытого песка в 2000 г. `bare2000_frac` (Global Forest Change, 30 м) с порогами шага 3
(`NEW_BARE_MAX, OLD_BARE_MIN = 0.30, 0.70`):

```
new: bare2000_frac < 0,30;   mid: 0,30-0,70;   old: bare2000_frac ≥ 0,70;   na: нет данных (севернее 70° с. ш.)
```

Поле характеризует оголённость поверхности в 2000 г., а не дату создания объекта; возраст присвоен контуру целиком.

### 9.6. Связь с признаками каскада

Шаг 3 использовал участки и сооружения ЕГРН как признак техногенного класса (правило a_nspd_on и зоны, п. 5.3): такой
признак имеют 72 033 контура, 1 723,6 км² (92 % площади класса). Поэтому доля площади в отводах частично задана самим
каскадом, и сопоставление с ЕГРН не является независимой проверкой точности техногенного класса. Сведения для каскада
(сервис WMS) и для сопоставления (сведения о земельных участках) получены раздельно.

## 10. Карты плотности

python/145_distribution_map.py (`--cls aeolian | anthropogenic`, `--method centroid | intersect`, `--cell`): показатель
«суммарная площадь песков класса в ячейке, га/км²». Способ centroid относит площадь контура целиком к ячейке с его
центроидом; способ intersect распределяет площадь по пересечению контуров с ячейками:

```
D_c = Σ_i area(i ∩ c) [га] / S_c [км²]         (intersect)
D_c = Σ_{i: центроид i ∈ c} A_i [га] / S_c [км²]   (centroid)
```

Ячейки в равноплощадной конической проекции Альберса (`+proj=aea +lat_0=66 +lon_0=75 +lat_1=63 +lat_2=70`). Шкала для
ячеек не менее 5 км: 0; 0,1; 0,5; 1; 2,5; 5; 10; 100 га/км²; цвета соответствуют карте 2022 г. Оформление: подложка
ALOS AW3D30, граница района, полосы вне покрытия маски, границы месторождений (на карте техногенных песков), крупные
реки OSM (146_osm_rivers.py), автодороги, города.

Растры плотности интерактивной карты (python/150_gee_upload.py `--density-grid`) построены способом centroid в
EPSG:3576 с ячейками 10, 5 и 2 км для эоловых песков, отмелей и техногенных песков; суммы по растрам совпадают с
площадями классов итогового слоя.

## 11. Ограничения метода

- Оценка точности относится к атрибуции генезиса внутри маски для версии до точечных правок; пропуски песков вне маски
  и точность отдельных пикселей не оценивались.
- Эталон сформирован одним экспертом по снимкам сверхвысокого разрешения; доверительные интервалы получены бутстрэпом и
  являются приближёнными.
- Сцены Sentinel-2 разных тайлов сняты в 2020-2025 гг., снимки эталона и сведения ЕГРН относятся к другим датам; часть
  расхождений может быть связана с реальным строительством, зарастанием или колебаниями уровня воды.
- Контуры менее 1 га находятся на пределе разрешения снимков; мелкие и узкие объекты описываются признаками на сетке
  30 м (GSW, GFC, Landsat) грубо.
- Разности высот ArcticDEM исключают общую составляющую эллипсоидальных высот, но не пространственно неоднородные
  ошибки мозаики.
- Сопоставление с ЕГРН носит операционный характер: оно выделяет места для адресной проверки и не устанавливает фактов
  нарушений.
